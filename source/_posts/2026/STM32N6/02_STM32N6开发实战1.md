#### 1.1 配置RCC 时钟
&emsp;在RCC选项卡中，我们选择外部高速晶振，这里和普通F1,F4,H7芯片配置不同的是，我们还要注意芯片的供电方式，N6的核心电压有两种不同方式供电，手册中的说明如下：  
![供电方式1_SMPS](Systemsupply_SMPS.png)  
![供电方式2_NonSMPS](Systemsupply_NonSMPS.png)  
SMPS:SMPS step-down converter（开关电源降压转换器）,是STM32N6芯片**自带**的一个开关电源降压转换器，这个设施的启用与否取决于硬件设施设计时是否对外部供电存在处理，能否让核心在没有转换器的情况下正常工作。我所使用的开发板并没有，因此这里需要将其变成“PWR_SMPS_SUPPLY”，完整的配置图如下：

#### STM32N6 工程真实目录结构说明 (基于 STM32CubeIDE)

本项目基于 STM32N6 系列微处理器开发。STM32CubeMX 在生成 STM32CubeIDE 工程时，采用了"**源码与 IDE 工作区严格分离**"的设计逻辑。

以下是本工程真实生成的物理目录层级及其核心功能详解：

##### 🗂️ 整体物理目录树预览

```text
📦 Project_Name (工程根目录)
├── 📄 Project_Name.ioc               # CubeMX 图形化核心配置文件
├── 📄 .mxproject                     # CubeMX 内部生成状态记录文件
│
├── 📁 Appli                          # 【纯源码区】应用核心代码 (不含任何 IDE 配置)
│   └── 📁 Core                       # 包含 main.c, 头文件及外设初始化 C 代码
│
├── 📁 Drivers                        # 【纯源码区】官方底层驱动库
│   ├── 📁 CMSIS                      # Cortex-M55 内核文件及启动汇编
│   └── 📁 STM32N6xx_HAL_Driver       # STM32 HAL/LL 库源码
│
├── 📁 Secure_nsclib                  # 【安全特性】TrustZone 相关的安全/非安全域接口存根 
│
└── 📁 STM32CubeIDE
    │   # 【IDE 工作区】所有的编译、链接和工程配置文件全在这里！
    ├── 📄 .project                   # 整个 Eclipse 工作区的定义文件
    └── 📁 Appli                      # 针对 Appli 应用的独立子工程文件夹
        ├── 📄 .cproject & .project   # CubeIDE/Eclipse 的核心工程配置文件
        ├── 📄 Project_Appli Debug.launch # 点击“Debug/Run”时调用的启动/下载脚本
        ├── 📁 Application  
        │   # IDE 内部虚拟映射的源码文件夹 (指向外层的 Appli/Core)
        ├── 📁 Drivers                # IDE 内部虚拟映射的驱动文件夹 (指向外层的 Drivers)
        ├── 📁 Debug                  # 编译输出目录 (包含生成的 .elf, .bin, .map 等文件)
        ├── 📁 Release                # 编译输出目录 (包含生成的 .elf, .bin, .map 等文件)
        └── 📄 STM32N647X0HXQ_*.ld    # 【关键】所有的链接脚本文件都在这里！
```

#### 2.6 添加自制文件夹
&emsp;由于后续开发需要添加非常多的驱动文件，因此这里提前说明如何添加自制文件夹/文件。
1. 在工程根目录文件夹`Drivers`下新建一个文件夹`BSP`
2. 在IDE中右键点击工程目录`Drivers`，选择`New->Folder`，
3. 在弹出的窗口中输入文件夹名称，**不要**立刻点击`Finish`，而是先点下面的Advanced >> (高级) 按钮。
4. 展开高级选项后，你会看到下面多出了一块区域。**勾选 Link to alternate location (Linked Folder)（链接到备用位置/链接文件夹）**。

5. 这时下面的路径框亮起了。点击旁边的 Browse... (浏览) 按钮。
6. 在弹出的窗口中，选择你刚刚在工程根目录`Drivers`文件夹下新建的文件夹`BSP`，然后点击 OK。

7. 最后，点击窗口右下角的 Finish。
&emsp;这样，你就在工程目录`Drivers`下添加了一个名为`BSP`的文件夹，并且这个文件夹的链接位置是工程根目录`Drivers`下的`BSP`文件夹。以后，你在这个文件夹下添加的文件，都会被链接到工程目录`Drivers`下的`BSP`文件夹中。
此时的工程结构如下：

```text
📦 Project_Name (工程根目录)
├── 📄 Project_Name.ioc               # CubeMX 图形化核心配置文件
├── 📄 .mxproject                     # CubeMX 内部生成状态记录文件
│
├── 📁 Appli                          # 无变化 
├── 📁 Drivers                        # 【纯源码区】官方底层驱动库
│   ├── 📁 CMSIS                      # 无变化
│   ├── 📁 BSP                        # 【自制区】自制驱动库
│   └── 📁 STM32N6xx_HAL_Driver       # STM32 HAL/LL 库源码
│   
├── 📁 Secure_nsclib                  # 无变化
│
└── 📁 STM32CubeIDE                   # 无变化
    ├── 📄 .project                   # 无变化
    └── 📁 Appli                      # 无变化
        ├── 📄 .cproject & .project   # 无变化
        ├── 📄 Project_Appli Debug.launch # 无变化
        ├── 📁 Application            # 无变化
        ├── 📁 Drivers                
        │   # IDE 内部虚拟映射的驱动文件夹 (指向外层的 Drivers, BSP在其中)
        ├── 📁 Debug                  # 无变化
        ├── 📁 Release                # 无变化
        └── 📄 STM32N647X0HXQ_*.ld    # 无变化
```

#### 2.7 添加自制文件 & 访问路径
&emsp;在工程根目录`Drivers`中的文件夹`BSP`添加相应代码文件，然后在IDE中右键点击工程右键flash,即可刷新进入到工程中。


&emsp;接下来添加文件路径，由于BSP后续内容较多，因此索引路径只有一条/${ProjName}/Drivers/BSP。操作如下：
1. 点击左侧工程树所选工程的总目录Project_Name_Appli,右键选择`Properties`->`C/C++ General`->`Path and Symbols`-> `Includes`选项卡。  
   ![添加自制文件 & 访问路径](Path_and_Symbols.png)  
2. 点击右侧的 `Add...` (添加...) 按钮。
3. **⚠️ 核心警告：绝对不要在 `Directory` 文本框里手动打字！**
4. 点击输入框下面的 `Workspace...` (工作空间...) 按钮。

### 3.添加代码

&emsp;在`Drivers/BSP`文件夹下新建一个文件夹`UART`，然后在`UART`文件夹下新建一个文件`uart.c`，在`uart.c`文件中添加以下代码：
```c
/**
 ****************************************************************************************************
 * @file        uart.c
 * @version     V1.0
 * @brief       串口驱动代码
 ****************************************************************************************************
 */
#include "uart.h"

/**
 * @brief   重定向C库的printf函数到串口
 * @param   无
 * @retval  无
 */
int __io_putchar(int ch)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, 0xFFFF);

    return ch;
}


/**
 * @brief   重定向C库的scanf函数到串口
 * @param   无
 * @retval  无
 */
int __io_getchar(int ch)
{
    HAL_UART_Receive(&huart1, (uint8_t *)&ch, 1, 0xFFFF);

    return ch;
}

```
&emsp;在`Drivers/BSP`文件夹下新建一个文件夹`UART`，然后在`UART`文件夹下新建一个文件`uart.h`，在`uart.h`文件中添加以下代码：
```c
/**
 ****************************************************************************************************
 * @file        uart.h
 * @version     V1.0
 * @brief       串口驱动代码
 *
 ****************************************************************************************************
 */

#ifndef __UART_H
#define __UART_H

#include "main.h"
#include <stdio.h>
#include "usart.h" //只有当你勾选了`Generate peripheral initialization as a pair of '.c/.h' files per peripheral`时才需要包含这个文件




#endif
```

&emsp;主函数中代码如下：
```c
...
/* Private includes ----------------------------------------------------------*/
/* USER CODE BEGIN Includes */
#include "./UART/uart.h"
#include "stdio.h"
/* USER CODE END Includes */
...
int main()
{
···
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
		 printf("hello world\r\n");
		 HAL_GPIO_TogglePin(LED0_GPIO_Port, LED0_Pin);
		 HAL_Delay(1000);
  }
  /* USER CODE END 3 */
    ···
}

```
&emsp;编译并下载(Debug)，可以看到串口打印出`hello world`，LED0灯每秒闪烁一次。


### 4.关于在工程上复制和创新

&emsp;在工程上复制和创新，原本在keil5 上是可以直接复制文件夹改名字就可以了，但是STM32CUBEIDE上他会针对你的工程文件进行独立的签名，这种签名非常多，如果手动改的话将会非常繁琐，并且每个加入cubeide的工程之间还不能重名，否则无法添加进cubeide，**因此我更建议**如果要在原工程上做开发，请直接只复制一个cubemx文件，即xxx.ioc然后将xxx更名为你需要的名字比如zzz，然后打开zzz.ioc文件，在新的文件夹下重新生成工程，最后直接在cubeide上添加文件，这样就不会出现重名的问题了。
